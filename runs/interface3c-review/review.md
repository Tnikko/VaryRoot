# 3c 独立观测部分交付

生产种子 curl-openldap-2018-seed-v4 的 3a/3b 包为输入。独立检查点仅发布两侧 partial_sample 回执，均为 pending。样本分母为尝试 1、生产接受 0、待验证 1。3d 尚未启动。

| 有限域 | 父版骨架 | 修复版骨架 |
| --- | --- | --- |
| 1 成功、空输出 | 未观测 | 未观测 |
| 2 正常数组含哨兵 | 外层调用 2 次，内层条件索引依次为 0、1 | 相同 |
| 3 非成功、空输出 | 外层调用 1 次，目标事件 0 | 相同 |
| 4 空值属性后有后续属性 | 未观测，遍历字段 null | 未观测，遍历字段 null |

观察器只接受两种良性投影。父版已知漏洞触发驱动未纳入本次实现。修复版第 1、4 类也未实测。第 2 类在已映射条件位置记录返回码、所属对象、空值标记与索引。条件的结果由预先登记的受控数组影子值提供。原目标读取次数为零，正常输入的到达见证与原访问实际执行须分别统计。步骤 05 classify 对本次两个已测输入分别使用 no_access、blocked，保留缺项 [1,4]、normal_witnesses 为空。每侧仅有原骨架表达式的唯一静态映射，本次数据不足以证明一般表达式插桩保真、真实产品的读取次数或第 4 类遍历行为。

## 输入、构建与运行

构建从 3b 的双侧骨架字节摘要和唯一目标跨度开始。src/build.py 对指定表达式进行影子替换，以项目锁定 Clang 18.1.3 编译，用只读输入中固定摘要的 GNU gold 在同一命名空间内链接两个独立 .so。out/build-lock.json 记录命令、源及产物摘要。out/header-digests.json 逐文件记录两个只读头文件包的内容。完整输入包、链接器和编译后源码一并保留。首次链接因隐式 memset 未解析而失败，改为显式初始化单个指针字段后通过。未执行完整的 libcurl 或 LDAP 服务。

执行使用 varyroot.sandbox.materialize 与 run_role 的 namespace 后端。验证器白名单含新观察器、其调用脚本、目标与版本绑定、契约、观察域。角色实际检查输入写入得到 EROFS，UID 1009，仅 lo，无 Docker socket。逐侧 execution、input_manifest、raw、receipt、publication 和 rejections 文件均在 out。raw 是验证器原始输出，receipt 是读入同一内容后的格式化 JSON。src/dispatch.py 使用独立检查点 SQLite 调用项目 Publication 签发和读取结果，同一回执重复提交得到同一 ready 摘要。生产种子账本仅以只读模式打开。

## 负测与证据边界

每侧实测 7 个拒收条件，覆盖请求、尝试、清单、观察域、映射歧义、种子包和契约摘要错配。5 个项目回归方法的实际输出见 out/tests.log，覆盖正常见证缺失、部分域、重复发布、进程终止后迟到回执、基础设施重试与案例级失败。另以既有合成数值夹具测试未定义源表达式分类，结果见 out/ub-fixture.log。这些故障注入属于回执协议与分类回归。实际双侧新观察器只产出本报告表中的良性输入观测。

复核时可从 out/before-raw.json 和 out/after-raw.json 检查逐条记录，用 out/build-lock.json、out/*-execution.json 和 SHA256SUMS 核对运行。源码在 src，源码与工件按提交时的内容归档。3c 未达到双侧四类全覆盖。
