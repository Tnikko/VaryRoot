# 下一审核点：真实候选池的独立取证与配对校准（待批准）

## 先行决策

本轮模型池只有适用域差异，没有硬分歧。步骤 4 不能预设三池会淘汰 `H_loop` 或修订 `S₀`。建议先对三份已锁定静态池逐项签发观察资格；不能运行的变体以 `unsupported_shape` / `case_exec_failure` 留在原始分母，不改写池。若要增加专门生成“判空后继续”硬分歧的第四批模型提案，另立 v2 池和预算，绝不覆盖本轮三池。

## 建议实施顺序

1. **4a 验证器适配与准入再核**：只用 `freeze.json` 的 8 个模型变体和离线对照；为每例编译唯一目标的前置观察器，保留真实安全访问、空值前阻断、OpenLDAP 输出槽契约与正常功能见证。观察器容器只读当前案例和契约，不读预测。若某例超出 3c 观察器能力，记录新能力缺口及原池 ID，不能静默剔除。
2. **4b 独立裁决与 B 登记**：在生产协调器按固定域取证；每例保留 `Observation/Verdict`、完整性摘要、请求围栏和分母。之后才给所属组揭示证据。三池分别创建 `random` / `divergence` 两组，共享该池和预算上限，随机组清单不能包含预测或其派生排序。
3. **4c B4/B6 与跨池横向记录**：将硬分歧与适用域差异分列，`uncovered` 不淘汰解释；预算耗尽且竞争解释仍相容时签 `unresolved`，不能伪装成 `keep`。记录首条有效区分证据的逻辑成本、终态、全量确定位置及池间 `S^*` 收敛。
4. **4d Agent C 能力门禁**：仅对 B 已签 `revise/keep` 的组评估真实 OpenLDAP NPD 的 C1 能力；若当前 C 编译器无法表达该形态，先提交接口增量，不用样本特判绕过。忠实生成双版查询并按表达式位置回归后方可成对冻结；`unresolved` 与 `backend_gap` 按现有协议交付部分结果。

## 验收材料

生产 SQLite 事件链、验证器构建锁与命名空间审计、两组选择/预算/揭示水位、B6 全量回查、双版查询逐位置五列记录（若进入 C）、跨池波动与峰值内存。所有报告与原始回执同时归档到 7server 项目目录及本机镜像，并逐文件核对 SHA-256。
