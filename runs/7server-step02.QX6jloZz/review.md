## 接纳决定

尝试 1，生产接受 0。去向为 awaiting_interface_review。两侧完整源码都经过 agent_a.facts_for 的只读形态检查，均返回 unsupported logical-prefix source shape。该函数只覆盖登记的数组读取示例。这是接口能力诊断，未执行该历史产品代码，也未派发生产 A4/A6 或创建生产 seed 状态。当前缺项是外部库调用返回状态、输出对象身份和有效性之间的独立契约依据，以及面向真实翻译单元的前端绑定。补丁本身不能核准这些事实。对尚未核准的事实保留来源、适用版本与阻断位置；解释器只能得出未覆盖。

## 服务器运行前提

宿主协调器已取得可直接执行的项目内 CPython 3.13.2，路径为 /dev_sdb/tq/VaryRoot/toolchains/cpython-3.13.2-linux-x86_64-gnu/bin/python3.13。基于开发工作站现有可迁移发行包部署，解释器与传输包摘要见 intake.json。在独立冒烟目录实例化现有 Ledger，读取空事件清单，并用同一解释器成功启动导入 sqlite3 的子进程。SQLite 版本为 3.47.1。上次重放根文件系统内的 Python 3.13.18 直接在宿主运行时缺少所需 glibc 版本，它仍可在自己的根文件系统中运行。

## 增量审核范围

1. 协调器沙箱。保留 run_role 的清单核验、输出目录约束和超时语义。增加显式配置的 namespace 后端，统一角色镜像解析与绑定。一次派发只挂载该角色的只读输入、只读根和独占输出；收据绑定后端、角色镜像与根文件系统摘要、尝试 ID、有效 UID、挂载、网络和退出状态。验收从真实协调器发起，检查缺文件、超时回收、迟到回执、随机角色隔离，以及同一逻辑请求只扣一次预算。步骤 1 的手工重放只能作为对照。
2. 工具链。批准后按原 VM 的角色镜像 ID 导入项目私有根文件系统并核验解包摘要。A 角色核验 clang18.lock.json 及编译器版本；验证器核验 registry 和原生二进制摘要。步骤 05 的验证器在构建时用锁定 Clang 编译，现有运行镜像交付预编译观察器，新增观察器还需要独立的可复现构建记录。
3. 源码与契约。先支持从已核源的翻译单元静态引用目标表达式及关联对象，记录所属提交、编译条件、调用边界、外部接口的版本与独立依据。使用自有的内存安全夹具核对对象绑定和正常路径见证。外部契约待审、映射不唯一、竞争解释不足或只有夹具见证时，保留对应的未决原因。真实候选的生产接受需要单独提交 A4/A6 合格证据。当前没有依据要求改动四元组 IR；若现有字段无法表达这些关系，再列出无法表示的最小示例申请变更。

本轮检查点为接口评审，下一步先验收协调器与工具锁的主调度路径，再评审真实源码的静态绑定。独立评测预留集未参与核源。
