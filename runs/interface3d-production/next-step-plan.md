# 待审：第 3 步真实模型提案器接入计划

本计划仅供审核；尚不启动模型调用或 Agent B 选例。

1. **输入边界和模型接口。** 从已接受的 v4 种子只读导出固定的源码切片、经核准的 OpenLDAP 参考契约、初始规约及竞争解释。模型调用在独立提案入口运行，验证器、选择器和 Agent C 继续断网。输入清单按组限制揭示水位，排除 reserve 与未揭示标签。每次留存输入摘要、提示词模板、模型标识、采样参数、原始回复、token 与费用。凭据由运行时注入，不写入项目工件或本地归档。
2. **三次独立生成与冻结池。** 以相同种子和候选解释做 3 次独立提案，记录生成随机性和失败率。候选先通过 AST/编译、目标映射、共享契约、单因素和作用域检查，再冻结三个互不覆盖的池。一个真实 NPD 种子仅用于接口与波动摸底，不作选例策略优劣的统计推断。
3. **四类准入账本。** 将每项提案标为「有效且形成新分歧」「有效但无新分歧」「提案自身缺陷」「语义合理但超出当前前端/验证器支持形态」。分层保留拒收原因与目标位置；未入池案例不得消耗 B 的验证预算。随机组只接收中性排序的冻结池。
4. **复核与交接。** 离线重放三池的准入结果和摘要，横向比较候选数、实质分歧和生成波动；补记 R08 的真实模型维度。交付原始提案与分类证据后再审第 4 步配对校准。先独立解决 7server 旧原生构建测试运行器与锁定镜像启动器不兼容的问题，明确可执行的全量回归门禁；不改变原生产工具锁。

审核时还需定下模型提供方式和运行时凭据注入路径；既有 Daybreak 权限不等于模型 API 配置。
