框架建设执行计划

交互式框架总图　·　IDEA 正文

目标是交付一套本地可重放的 C/C++ 内存访问规约校准框架。首版覆盖空指针解引用和连续缓冲区越界访问。给定一个种子，最终可以从查询差异追到条款修订、独立证据和原始访问位置。

本次审核的决定

建议先批准建设顺序及第一阶段的设计范围。审核通过后，首批提交为工件字段契约、状态语义表和两条贯穿实例。具体契约可以在实现解释器之前调整。

建设顺序与完成条件

展开阶段可查看依赖、交付内容与失败处理。各阶段使用构造材料验收接口行为。框架整体落地后再开展独立效果评测。

011A · 静态工件契约与规约 IR项目起点

先定一次访问如何在源码、骨架、规约与查询之间被识别。

具体工作
交付 TargetRef、Fact、Clause、Prediction、Observation、Verdict、Decision、Revision 的字段、类型、版本、必填条件与引用关系。Fact 标出源码事实、接口保证或骨架假设。Clause 分开记录适用域和逻辑方向。
关键边界
用 NPD 的“检查后继续／退出”和 OOB 的“容量 8、偏移 6、宽度 2／3”各写一份完整实例。示出缺少单位时的未覆盖、前后证据冲突时的退回，以及确定修订后应改变和应保持的位置。
完成条件
验收工件是一份契约目录、两条贯穿实例和一张状态语义表。任取一条修订，能追到原目标、旧预测、独立证据及新增事实需求。
Fact 与 Clause
Fact 分开记录来源类别、来源定位、核准状态与适用域。保留假设的原始出处；待审假设只阻断依赖它的推导或门禁。Clause 用 Source、Propagation、Guard、Sink 绑定对象、路径和访问，并独立声明适用域与逻辑方向。
Decision 的独立契约
decision.json 记录种子、组、轮次、父规约、所用 Prediction 与 Verdict 版本、决定、理由及剩余分歧。修订决定引用 Revision，保留与未决决定分别记录支持证据或停止原因。每条 Revision 列出判断改变的位置、应保持的位置及新增事实需求。
NPD 贯穿实例
固定目标和接口，比较记日志后继续、退出或跳到清理处。另设先修正指针再安全使用的分支；检查时的值和访问时的值分别绑定。验证违规到达、安全绕过和安全到达三种观察。
OOB 贯穿实例
容量 8 字节来自独立契约，偏移 6 字节。宽度 2 的单次访问贴边合法，形成案例级确定反例还需正常见证及声明域完备依据；宽度 3 的可行越界访问可作正例见证。任意宽度起点检查被后例反驳，修订须同时回查宽度 2；单字节条款对两例均未覆盖。
021B · 确定性解释器规范依赖工件契约

把条款变成可重放的预测。

具体工作
实现类型校验和首版原子关系：对象身份、空状态、路径阻断、单位转换和区间包含。解释器消费前端提供的事实，输出条款版本、推导步骤和缺项。
关键边界
分别处理应报、不应报和未覆盖；相反结论同时可推导时返回规约冲突。未绑定变量不得被当作假值。
完成条件
两份贯穿实例可由同一入口解释。重复运行得到相同推导；删除容量单位时，结果明确指出哪项推导被阻断。
推导优先级
工件结构错误退回 1A。合法的未知事实只阻断依赖它的证明；其他条款仍可给出结论。记录不适用、缺事实或缺少条款等原因。对同一目标和域，分别收集支持应报和不应报的推导；两方均成立时返回冲突并停止该预测进入选例或冻结。
必要条件的验收
“只有 return 才保护”表示保护蕴含 return。须确认适用域、证实该路径没有 return，并有从相关故障到目标的报告判据，才导出应报预测。仅凭语法匹配失败无法证明路径可行。若 return 只是充分条件，单凭缺少 return 推不出保护或违规。
缺失单位
在同一 OOB 案例中仅向解释器隐去容量单位，验证器仍用独立核准的字节容量。若无其他推导，预测为未覆盖，并定位到容量单位绑定。若验证器自己的契约也缺单位，则另行返回待定。
03本地协调器依赖工件契约和预测接口

让预测登记、选择提交和证据揭示具有明确先后关系。

具体工作
定义运行目录、状态转换表、角色输入清单和提交协议。模型提案先暂存，完整性校验后提交。将选择 ID、预算扣减和提交状态作为同一操作处理。
关键边界
中断、重复提交和并发写入分别处理。证据修正和预测勘误增设版本，旧记录保持可重放。
完成条件
在选择已提交、证据尚未返回时中断并恢复，仍取回同一选择且预算只扣一次。角色只能读取当前阶段允许的工件。
账本与隔离
以组、种子、轮次和选择 ID 标识一次逻辑验证。选择、扣费及提交原子完成；待定亦占预算，同一提交的故障恢复复用原记录。预测勘误、证据更正或域变更追加带父版本的记录。分歧组和随机组从开发校准开始隔离已揭示标签与模型上下文，独立评测材料另行隔离。
更正传播
修正契约、证据或位置映射后，按引用版本标记受影响的裁决、决定与回归记录待复核。旧冻结包保留原依据；新结论形成新版本。
04源码前端与 Agent A依赖位置、事实与状态接口

把一处修复变成有来源依据的初始解释。

具体工作
前端登记给定源码快照、访问位置、类型和依赖事实。模型提出骨架、桩函数契约、S₀ 和竞争解释。逐项保存原程序与骨架的对应关系。
关键边界
将“可提出候选”与“已接受种子”分成两个状态。此阶段可交付待验证种子；下一阶段接入证据后才完成接受门禁。
完成条件
每项关键假设均可定位到依据或待核准项；映射歧义保留原因。契约未核准的种子无法被误提交为已接受。
阶段交接
阶段 3 交付待验证种子、原代码与骨架的位置和对象映射、待核准假设。阶段 4 接通 A4 的独立证据与 A6 的解释器验收后，协调器才可提交已接受种子状态。
05独立验证器依赖 A 的种子包和观察契约

先实现证据如何成立，再实现 B 如何使用它。

具体工作
为受控开发材料设计 NPD、OOB 两类观察适配器。记录目标身份、路径和访问意图；OOB 的容量取自独立核对的目标对象契约。
关键边界
区分单次观察、完整声明域、待定和运行失败。种子门禁接受安全退出，也接受状态修正后正常到达。
完成条件
一条违规见证可追到具体访问；确定反例附正常见证和覆盖依据。截断观察域时不得凭无违规记录生成完备结论。接通 A 的接受门禁。
06Agent B 与校准闭环依赖解释器、协调器与独立证据

让选例和修订能够分别审计。

具体工作
模型提出对照及保持条件。程序生成三值预测矩阵并按已登记策略选例。证据揭示后，区分案例错误、解读错误和条款错误。
关键边界
每条 Revision 列出改变的判断、应保持的判断、新增事实需求及适用域。支持保留、未决、重新建模；明确选择成本和停止原因。
完成条件
从一条修订能重放当时的候选、预测、选择与证据；若证据支持原解释则可交付 S*=S₀。证据不足时保留未决，不自动提交定稿。
跨模块退回
B4 发现骨架或契约失真，退回 A2。独立证据核准、解读忠实且所有候选均遭反驳时，退回 A5。退回携带触发位置、证据版本和归因，不覆盖原运行。
07Agent C、回归与冻结依赖稳定的规约版本和 Revision

把条款变化落实为可定位的查询变化。

具体工作
按语义、绑定、适用域与版本复用谓词。由 C 组装 Q₀、Q*，对本地开发材料逐目标表达式回归。建立条款到谓词、谓词到告警的映射。
关键边界
分别记录规约未覆盖、后端取不到事实、位置歧义与真实零告警。实现偏差返回 C；Q* 忠实于条款但与确定证据冲突时返回 B。
完成条件
Q₀ 忠实于初始规约，Q* 同时通过规约与确定开发位置的门禁。交付两版工件、版本清单与重建入口；失败运行留下部分工件与原因。
默认与匹配
明确登记未覆盖位置默认无告警，保留默认原因；该位置经证据确定为正例时计漏报。C4 按源码版本、文件和目标表达式跨度对齐。歧义单列，同行或同文件的其他告警不能代替目标命中。

框架交付时如何验收

走查正常修订、有据保留、证据未决和后端缺口四条路径。规约推导由 TargetRef、Fact、Clause 得到 Prediction；取证由目标、契约和声明域内的 Observation 得到 Verdict。两条记录在 Decision 汇合，形成 Revision 时记录改变的判断、应保持的判断与新增事实需求。

选取一条有来源依据的修订，从冻结包反向定位到谓词、条款、触发对照、验证记录和源码位置，再正向重放已保存的决策。另检查一次证据不足和一次后端失败，验证系统能准确停在对应模块并返回部分结果。
