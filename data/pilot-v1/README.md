# 首轮实验数据 pilot-v1

这批数据有两种用途。24 个原创 C/C++ 合成目标位置可直接编译回放，用于检验规约预测、选例预算和观测记录。15 条历史修复候选用于后续抽取种子与建立独立评测集。两者按不同单位计数。

| 部分 | 内容 | 使用阶段 |
| --- | --- | --- |
| [开发案例清单](development/models/cases.jsonl) | N01–N12 为空指针访问模型，O01–O12 为连续缓冲区访问模型。每类六对，前两条是种子，后十条进入候选池。共 12 个 C11 和 12 个 C++17 位置 | A 读取种子对，B 读取候选源码与位置 |
| [已登记预测](development/predictions.jsonl) 与 [首轮选择](development/selection.json) | 两个类别各有两种初始解释；随机与分歧组每次选四个位置。选择记录固定了池和预测文件的 SHA-256 | 验证器调用之前 |
| [历史开发候选](development/historical.jsonl) | curl 的 6 条维护者记录，含 NPD 1 条、OOB 5 条。每条修复 SHA 已向上游提交接口核实，附父提交和变更的 C 源码或头文件路径 | 真实补丁的契约、根因、目标定位与修复簇审查 |
| [修复版本源码索引](development/fixed-files.jsonl) | 本地固定了上述提交涉及的 8 份产品源码或头文件快照及 6 份对应版本的 COPYING，逐文件核对 Git blob，并记录来源和 SHA-256 | 离线核对修复版本的对象关系与接口契约 |
| [历史预留候选](reserve/historical.jsonl) | Exiv2 的 9 条维护者公告，含 NPD 2 条、OOB 7 条。记录公告、修复版本和公告引用的变更链接 | 独立评测者保管，冻结后才向评测运行提供 |
| [夹具验收记录](qa/smoke.json) | 全清单编译回放的汇总和八个已登记批次的检查结果 | 数据维护者核对，排除在选例输入之外 |

## 合成样本的契约

每个 ID 对应一个函数中的一个目标调用。相邻奇偶 ID 是一对，查看清单中的文件、符号和一基行号即可定位。第 1 对是修复前后骨架，第 2–6 对见下表。C++17 组覆盖与 C 共有的指针和整数语义，当前对照没有涉及 RAII、模板或容器生命周期。多个案例会共享代码写法，独立种子数按两个种子对计算。

| 对照 | NPD | OOB |
| --- | --- | --- |
| 第 2 对 | 记录后继续／记录后退出 | 同一项起点检查下读取 1／2 字节 |
| 第 3 对 | 检查其他指针／目标指针 | 使用其他缓冲区容量／目标容量 |
| 第 4 对 | 部分／全部模式阻断空值 | 部分／全部模式检查访问上界 |
| 第 5 对 | 提前退出／跳到清理出口 | 相同完整区间检查下提前退出／跳转 |
| 第 6 对 | 检查并使用同一别名／检查其他对象后使用别名 | 比较时采用字节偏移／元素偏移，实际请求均按字节观测 |

NPD 骨架以目标、另一对象的可用状态及模式三个布尔量为输入，每个位置穷尽 8 个组合。目标标记接收实际传递的指针并记录是否为空。OOB 骨架以目标容量 {0,2,4,8}、另一对象容量 {2,8}、原始偏移 {-1,0,1,2,3,4,6,7,8,9}、宽度 {1,2,3} 和两种模式为输入，每个位置穷尽 480 个组合。第 2 对使用固定请求宽度，第 6 对把原始偏移按两字节元素解释。探针记录到达位置的实际字节偏移和宽度，验证器与目标对象的登记容量比较。原始输入组合数包含投影到相同请求的情况。

标记函数只记录访问意图。出现一次违规请求即赋正例；完整枚举后有正常使用且其余请求均合法或阻断，赋模型域内反例。全部阻断保留待定。运行中断的输出不能作为该位置的完整证据。这批模型没有刻意截断的待定样本。

## 预测、选择与回放

本批预测由数据作者在回放前登记。NPD 的 H0 将使用前检查同一指针视作充分保护，H1 要求每条空值路径都绕过该目标。OOB 的 H0 接受访问前可见的偏移上界检查，忽略其覆盖模式、对象、单位和宽度；H1 要求实际目标对象上的完整字节区间在所有到达路径均合法。两者都对无保护的种子位置预测应报。这些是夹具的候选解释，正式历史种子需独立提取规约。

在 WSL Ubuntu 中执行下列命令可单独核对两个种子和一个候选。正式选例时将参数替换为 selection.json 中本组已登记的 ID，使用 `--trace` 输出逐输入证据。回放器只依赖 Python 标准库和本机 C/C++ 编译器，编译产物使用临时目录。

```sh
cd /mnt/f/VaryRoot/data/pilot-v1/development/models
python3 replay.py N01 N02
python3 replay.py --trace O04
```

验收使用 WSL Ubuntu、GCC/G++ 15.2.0、Python 3.14.4。24 个位置共执行 5,856 个输入组合，得到 10 个模型域内正例和 14 个模型域内反例。夹具属于有意构造的对照，开发观测可用于检查工作流能否区分两种解释。对未见代码的检测收益须由冻结后的独立评测估计。

## 历史候选的来源和纳入规则

2026-11-18 取维护者公开数据中发布日期位于 2017–2024 年、公告含 CWE-476、CWE-125 或 CWE-787 的记录。curl 还要求 GIT 范围能确定唯一完整修复 SHA；Exiv2 取仓库公告接口本次返回的前 100 条后按相同年份与 CWE 条件过滤。该清单是方便核查的历史样本，不是两项目的完整漏洞目录。[curl 维护者数据](https://curl.se/docs/vuln.json) · [Exiv2 维护者公告接口](https://api.github.com/repos/Exiv2/exiv2/security-advisories?per_page=100)

curl 的变更文件只能用于缩小源码核对范围。Exiv2 的公告链接可能包含原始引入变更、回移或共同修复，有些记录只有修复版本。两条公告引用同一 PR 时先归入同一待核查组。评测者应核对修复提交、根因、代表版本及访问位置，再决定是否纳入分母。开发和预留均来自公开资料；正式实验另行记录模型版本及既有训练数据可能带来的污染。

在本目录执行 `sha256sum --check SHA256SUMS` 可核对整批文件。正式运行另存本次使用的清单摘要、查询包和数据库版本。
