# 阶段 4 · 验证请求与观察接口

独立验证器回答一个限定问题：给定版本的案例，在指定对象、目标操作、契约和观察域下，有什么证据支持定标签？它可服务 A4 的种子前后核对，也可服务 B 已提交的案例选择。A6 的候选解释对照由解释器承担。A 的种子验证单记启动成本，B 的已提交请求占本组验证预算。

## 输入投影

| 允许的输入 | 必需绑定 |
| --- | --- |
| 请求与执行上下文 | run、request_id、attempt_id、token、manifest 摘要、只读工具清单、语言／ABI／构建和探针版本 |
| 选中案例 | 原创受控骨架与驱动、快照和变体摘要、分配的目标 ID。种子前后分别绑定请求，不给出期望标签 |
| 目标与契约 | 经核准的 TargetRef、实际操作角色、映射版本、Contract、对象身份与代次、适用路径、访问前置条件及其独立来源 |
| 观察域与覆盖 | Domain 版本、合法输入与模式、正常功能见证要求、枚举或已核准的等价类证书、停止条件 |

协调器按字段投影生成角色专属 input_manifest.json，每项绑定角色内相对路径、摘要、长度与版本。白名单同时适用于清单、挂载的内容及辅助文件的依赖闭包。实际案例源码中的条件语句必须保留；候选 Guard 条款、竞争解释、预测矩阵、选择理由、查询、告警与预期标签均排除。接受模型构造的桩时须引用已审查的接口保证，不能让桩或待检条件自行填写目标容量或预期观测。缺少必需独立依据返回诊断。文件可见性边界沿用[角色输入协议](../phase-2/visibility.md)。

## 观察与结果

每条 Observation 引用请求、尝试、目标、契约、观察域、输入、故障模式、路径或路径类、目标事件及执行状态。条件决策记录是否到达该操作；未到达须给出阻断位置或受核实的路径完成记录。丢失事件、提前死亡、未成功启动均不能推断为 blocked。有多次动态访问时按同一静态目标记录 occurrence，确定反例的依据应覆盖所有相关访问。

对到达事件附[适配器载荷](adapters.md)，对整次请求另交覆盖记录与[裁决或诊断](verdict.md)。数值若可超出通用 JSON 数字的精确范围，按带符号十进制字符串序列化，并另存源位宽和符号性。一个失败执行不能凭残留的标准输出自行签发裁决。

## 交付与恢复

验证器只能写本尝试的私有 staging。先写完整观察、覆盖及结果文件，刷新关闭并计算长度和 SHA-256；回执包含 run、request_id、attempt_id、token、输入清单摘要、退出分类和所有输出引用。最后同卷原子改名发布完成回执。工作进程无权揭示标签或改变种子状态。

协调器先核对当前围栏和完整性，再通过 T1 登记 publishing，提升经校验的对象，T2 提交 ready，最后按授权交付或揭示。当前尝试重复递交同一摘要只接纳一次；有效尝试矛盾回执进入 conflict，过期尝试归档。失租时先查有效回执及是否已在发布；确认无有效回执才废止旧尝试，沿用 request_id 重派。预算在逻辑请求提交时处理。[提交、预算与恢复协议](../phase-2/recovery.md)
