# 原代码到骨架的映射与保真检查（A2、A3）

A2 的模型提案逐项登记保留、删减和替代的程序节点及理由。A3 的程序核对可追溯的结构、类型、作用域、映射和必需契约；需要语义审读的保证进入待核准清单。可编译只说明骨架可解析和构建。

| 检查项 | 骨架必须保留的区别 | 核查或退回条件 |
| --- | --- | --- |
| 目标访问 | 原始目标的对象、读写角色、实际访问宽度及求值位置 | 登记父子快照、TargetRef、角色与依据。拆成“计算地址＋读取”时只匹配读取节点；两处读取均可能对应则报 ambiguous |
| 路径 | 进入故障分支的谓词、分支方向、退出边及清理后的后继 | 检查故障模式能否绕过本次目标，保留正常分支。goto 的目标若经清理再次返回使用点，就不能断言阻断 |
| 状态与值流 | 重赋值前后的指针值、别名、成功与失败分支、新值的契约 | 保留修正事件及其对实际操作数的作用。另一个变量变为有效，不能自动证明旧别名有效 |
| 数值与单位 | 目标对象、容量来源、偏移及宽度、类型转换和单位 | 桩若借用待检 Guard 中未经核实的长度作为目标真实容量，退回补独立依据 |
| 替代与删减 | 调用副作用、条件依赖、对象和路径上的关系 | 源码证据能支持与目标无关时才删除。缺少副作用摘要时保留原调用或提出待审假设。删减前后的必要控制边和值流边均须可对应 |

**映射记录。** 每项含父子 TargetRef 列表、变体、构建配置、来源链、变换种类、子节点操作角色、证据引用、mapping_status 和核准状态。前后版本可分别先映射至各自骨架，再登记配对关系。新增访问或删掉访问时记录该版本的缺席与依据，不伪造一对一目标。仅有缺席证据时，另核对修复后正常功能可达及该缺陷范围是否受保护。

**两类 NPD 保护的交付形式。** 提前退出保留“前态 p 为空 → 分支命中 → 退出或跳到确实绕过目标的出口”。Propagation 仍绑定故障来源；Guard 的依据是该路径无法到达目标。状态修正保留“前态 p 为空 → 执行重绑定 → 在已核准条件下新值有效 → 目标读取新值”。Propagation 指明到达时操作数对应哪次定义；Guard 的依据是到达状态合法。若修正操作还可能失败，应保留失败后继和返回保证，不能把条件修正简化为无条件成功。

**交付或停止。** 对依赖闭包内的每项假设登记 accepted_for_scope、pending 或 rejected 的审查结论，分别映射为 Fact 的 approved、pending、rejected。必要映射或契约未核准时交付 seed_pending，列明受阻条款及所需来源。与该种子无关的未核准提案只作历史记录，不进入接受依赖闭包。
