# S₀、竞争解释与待验证种子包

本阶段的正常终点为 seed_pending。A5 可以先形成候选草案；A4 的独立证据与 A6 的解释器检查齐备之后，协调器才有权把对应版本标为 seed_accepted。A、验证器、解释器分别交付提案、裁决、推导；任何一方自行写入的 accepted 字符串都不构成状态提交。

## 最小交付清单

| 工件 | 内容 | 消费者 |
| --- | --- | --- |
| 种子清单 | seed_id、版本、run_ref、修复前后 snapshot_ref、补丁摘要、配置、范围、契约和域版本、当前状态、阻断原因、直接依赖 | 协调器、A4、A6 |
| 位置与映射索引 | 目标操作角色、原代码及骨架的 TargetRef、origin_trace、父子映射、适用的定义级或调用点级策略 | A3、A4、C4 |
| 骨架提案与审查表 | 节点、变换、保留的条件与状态、桩契约、Fact 引用、支持来源和审查者。每条重要假设绑定到原始访问或条件 | A3、独立契约核准者 |
| 候选规约包 | baseline_spec_ref、active_model_ref、hypothesis_set_ref、父版本、变化依据。S₀ 及每个候选均含类型化绑定、四字段、适用域、逻辑方向和源码依据 | 1B 解释器、A6、B |
| 证据槽与检查结果 | 阶段 3 可以将 before_verdict_ref、after_verdict_ref、candidate_check_ref 留空，并明确标 pending。填入时记录依赖版本、作用位置和检查结果 | A4、A6、协调器 |

竞争解释应指向同一目标和种子前后语义。A5 可提出不同 Guard 或 Propagation 条款，但不能通过偷偷改变输入域让每个解释成立。A6 分别保存解释的两版推导，保留解释进入 accepted 集合的理由和被排除项；只有一个有据解释时如实交付可接受种子，另记缺少可作分歧选择的解释对。没有任何合格解释则回 A5。

## 接受门禁

下列六项为同一包版本上的合取条件。每项须为 true，未知、未提交或过期均阻断。

| 检查键 | 取 true 的条件 | 阻断时 |
| --- | --- | --- |
| mapping_ok | 必需目标及映射已核准，按预登记角色能唯一定位；需要跨版本配对时配对亦成立 | 留 seed_pending，A3 返回歧义项 |
| contracts_ok | 进入本包依赖闭包的契约及假设均在声明范围内核准，拒绝项已剔除或修正 | 回 A2；错误对象或缺单位分别定位到相应条款 |
| before_ok | A4 获得与故障对象和目标对应的修复前确定正例 | 交验证器补证，或输出部分结果 |
| after_ok | A4 获得修复后正常见证及声明域内保护依据；既接受退出也接受安全到达 | 证据不足留待验证，仍有违规时重查种子范围 |
| candidates_ok | 初始规约及当前拟接受的解释通过类型检查，对前后给出分别为 report、quiet 的明确预测且无冲突；另列不合格解释 | 解读或候选错误回 A5 |
| versions_ok | 所有引用可解析且绑定到当前快照、构建配置、契约、域、映射及解释版本；没有待重新验收的依赖 | 由协调器重算失效范围，拒绝旧检查结果 |

上述条件只是提交资格。实际提交还需持有协调器写权限、当前状态为 seed_pending、匹配期望的包版本。阶段 3 可生成诊断及完整的待验证种子包；阶段 4 接通 A4/A6 前，缺失的证据槽保持空值。

## 返工协议

- **B4 → A2。** Decision 记录骨架或契约失真，协调器创建子包并使当前工作版本回到 seed_pending。只为受影响节点、映射、假设及引用它们的聚合工件升版，旧包保留。失去对应关系的旧 Verdict 不得充当新包的门禁。原始观测须核对操作、对象、契约和域；只在仍适用时复用或重新裁决。A3 完成核准后，再经过 A4/A6。
- **B4 → A5。** 在证据可信且所有现有解释均被反驳时，复用合格骨架、映射、事实和证据，仅升版工作规约、解释集及包清单。保留首次登记 S₀ 和对应 Q₀ 的固定引用；新解释不得覆盖基线。新工作包回到 seed_pending 以重验解释，未变化且依赖有效的 A4 裁决可直接引用。A6 通过后恢复 B。新预测标 post_remodel，登记 parent_decision、commit_seq、组内可见证据水位与集合摘要。已使用的预算和已知证据随本组继承。

状态、快照与揭示先后遵循[阶段 2 权限与版本协议](../phase-2/visibility.md)。这两个回退分别改变程序模型或根因解释，不能共用“清空种子重来”的恢复策略。
