## 对同一行、宏与调用上下文的核对

用下面五行 C++17 输入进行两次独立语法解析，仅读取 Clang JSON AST 的种类、结构路径、拼写字节跨度和宏调用位置。输入采用 UTF-8、LF，含末尾换行。

```cpp
#define PAIR(x) ((x) + (x))
inline int read0(const int (&a)[2]) { return a[0]; }
int f() { int buf[2] = {3,5}; return buf[0] + buf[1]; }
int g() { int buf[2] = {3,5}; return PAIR(buf[0]); }
int h() { int buf[2] = {3,5}; return read0(buf) + read0(buf); }
```

实际环境为 Ubuntu Clang 21.1.8，输入 SHA-256 为 df23c015141abc7ebaf6f5b40ed6be3138f203543b5971bf47b021b7ed077344。解析命令为 `clang++ -std=c++17 -Xclang -ast-dump=json -fsyntax-only -x c++ -`。以各 FunctionDecl 为根，对 inner 数组从零计子节点序号。两次得到一致的位置与相对路径。

| 样本 | 实际观测 | 对设计的约束 |
| --- | --- | --- |
| f 的两个读取 | 拼写跨度 [118,124) 和 [127,133) | 同行行号相同，表达式跨度与 AST 身份不同 |
| g 的两次宏实参使用 | 两个跨度均为 [179,185)，展开起点同为 174；相对 AST 路径分别为 0/1/0/0/0/0/0 与 0/1/0/0/1/0/0 | 单靠拼写／展开坐标仍会碰撞。保留展开后的两个目标；目标后端若无法区分则标 ambiguous |
| h 的两个调用 | 函数体读取跨度 [73,77)，两个调用跨度 [227,237) 和 [240,250) | 定义级计一个读取；调用点级另附调用锚点。此核对只覆盖源码 AST，优化后内联位置匹配须在后端验收 |

## 接受门禁的复核口径

对六个门禁输入逐项取 true、false、unknown，只有六项全 true 的组合具备提交资格。另查两类近似通过情形：未核准契约加上“骨架可以编译”，以及映射有歧义加上“同一行已有告警”，均应停留在 seed_pending。A3 静态核准、A4 行为裁决和 A6 相容性检查各自落盘。此处验收设计规则及实例，完整前端、跨版本映射器与协调器提交隔离留待编码后联调。

本次按 seed.md 的六个门禁键在临时 SQLite 内存表中枚举了 729 组设计向量。逐项使用显式真值判定后，只有一组具备提交资格，另外 728 组均含 false 或 unknown。该检查核对合取规则；协调器写权限及并发提交行为尚待实际实现验证。
