# 提交、预算与恢复协议

## 一笔请求，若干次执行

预先登记三类独立预算账户：每个运行的 B.verify、C.repair.Q0、C.repair.Qstar。random 与 divergence 以及各随机重复分别开户。两个 C 账户初始额度相同；不得借用、阶段回退后再领或合并统计。**首版选择组间独立验证**，即使材料相同也分别派发。组内可以恢复已提交的同一请求；本地计算耗时和物理重试次数另记。

| 账本实体 | 身份与必要字段 | 拒绝条件 |
| --- | --- | --- |
| Command／Selection | 调用方重试键、参数摘要、run、round、prediction_batch、按序案例清单 | 同一重试键不同参数；过期运行版本；清单含重复位置 |
| Request／Charge | request_id、账户、业务键、输入摘要、状态、active_attempt。Charge 对 request_id 唯一 | B 的业务键含运行、案例版本、目标、契约、观察域及验证器配置。同组重复同一选择意图复用原请求；有意的新测量须预登记独立测量号。跨组必为新请求 |
| C 修复意图 | query_version_lane、父查询摘要、诊断引用、修复轮号、输入摘要 | 一次有意的新谓词／查询修复在生成提案前收费。相同提案的重新运行沿用原请求；诊断后发起下一次语义修改另收费 |
| Attempt | (request_id, attempt_id)、token、owner、启动身份、时限、心跳、暂存目录、状态 | 唯一 attempt_id；非当前令牌不能续租、预留发布或改变请求状态 |
| Publication／Artifact | 发布意图、暂存来源、期望摘要和大小、正式位置、schema、依赖、状态 | 引用尚未发布不可进入角色清单；既有对象的字节不匹配不得覆盖 |
| Event／Reveal | 单调事件号、运行与组、命令重试键、类型、不可变引用 | 同一请求／证据版本对同一组只能首次揭示一次 |

**选择事务。** 一个写事务中先查幂等重试键，再验状态、整批余额及输入摘要，写 Selection、新请求、唯一费用项、派发项和状态事件，余额不得小于零；任何一步失败整体回滚。外部进程只在提交成功后启动。派发者先在账本预留尝试及短启动租约，再启动并登记进程身份。若在两者之间中断，恢复按租约处理。一个令牌只允许一个执行者领取。请求因待定、工具失败、编译未过或提案未采用都不退还逻辑预算。基础设施重试另设预登记的次数或截止时间，耗尽返回 failed；无法无限占用研究运行。

## 文件发布与可见性

1. 模型提案和验证器输出都写入私有 staging。执行器在当前尝试目录完成结果，刷新并关闭结果文件；回执写入同目录临时文件，包含 run、request_id、attempt_id、token、输入 manifest 摘要、输出清单／长度／SHA-256 和退出状态。最后在同一文件系统原子改名为完成回执。回执出现前只能视为在途。
2. 协调器校验令牌、输入和输出、schema、来源与依赖；将输出复制到执行者不可写的协调器暂存区再校验。以当前尝试仍有效为条件，在事务 T1 登记 publishing 意图、摘要和暂存位置，锁定接纳的回执。此状态由发布恢复器负责，租约扫描器不得重新派发。
3. 从协调器暂存区将对象提升到同卷、只读的正式对象区。确保文件及目录项按目标平台的持久化契约落盘，然后再次核验摘要。事务 T2 将意图和工件标为 ready，并接纳尝试。正式文件即使已经存在，未通过 T2 时也不能被下游读取。
4. T1 后中断，按意图补齐提升；重命名后、T2 前中断，核验已有对象后补 T2。若暂存丢失且正式对象不存在，尝试从原回执重建相同字节；无法恢复则记录发布失败，不暴露悬空引用。T1 前的孤儿与未引用对象隔离，清理前先核对待发布意图和活跃尝试。组内交付另行提交，不能用对象存在代替授权。

SQLite 的事务覆盖库内记录。普通工件的原子改名、刷盘和断电后的目录项耐久性需要单独验收。实现时固定本地文件系统、SQLite 日志模式和同步设置；若平台未证实断电耐久，验收声明限定为进程崩溃恢复。[SQLite 原子提交说明](https://www.sqlite.org/atomiccommit.html) · [同步设置](https://www.sqlite.org/pragma.html#pragma_synchronous)

## 重启后的确定性判定

先读取账本。终态按已登记结果重放；publishing／ready 走发布／交付恢复；queued 且尚无尝试则派发。对 running 只检查账本指定的当前尝试目录，顺序如下。

| 当前尝试的可核验事实 | 动作 |
| --- | --- |
| 有有效完成回执，输入、身份、摘要均匹配 | **取回**。即使租约刚过期，只要尚未被废止也可条件提交 T1。与回收争用时，以先成功改变账本状态的事务为准 |
| 无回执且租约有效，执行者未确认终止 | **等待**。重新监听同一目录；启动租约内也可等待。PID 搭配进程启动身份和主机启动标识，PID 重用不能证明活跃 |
| 无回执，执行者已确认终止或租约失效 | **重跑**。一个事务废止旧令牌并预留下一个 attempt_id；启动后仍用原 request_id。旧进程迟到的输出仅归档，不能覆盖当前结果 |
| 有回执但摘要、身份或内容不合格 | 隔离并记协议错误。不可当作有效回执或一直等待；是否重试由预登记的基础设施策略决定 |

同一有效尝试重复返回相同输出摘要，幂等确认；同一有效尝试的第二个不同输出摘要进入 conflict，保留两份材料。来自已废止尝试的不同结果按过期处理。租约由协调器控制，心跳带令牌并条件续期。协调器重启后使用同一主机启动代次及可比较的单调时间；主机重启或时间基准不可比较时先查回执，再废止无法续证的旧租约。
