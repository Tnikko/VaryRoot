# 阶段 2 · 正向与故障复核记录

日期为 2026-11-19。复核对象是协调器详细设计。以下序号和额度是说明协议的验收向量，并非 pilot 实验结果。阶段 1 的位置与裁决定义见 [NPD](../phase-1/npd.md) 和 [OOB](../phase-1/oob.md)。

## 正向走查

**NPD，分歧定位到错误的 Guard。** A 登记待验证种子 → A4 获得补丁前后的独立证据 → A6 接受能解释种子差异的解释。分歧组 B 对 N.log@1 登记初始预测，提交选择。假定其 B.verify 初始余额为 2，此时变为 1；随机组余额仍为 2。验证器收到该位置与契约，观察到空输入继续到达目标。发布 ready 时 B 尚看不到标签。Reveal 提交后才能把 positive 放入 B 的输入清单。B4 将问题归于弱 Guard，B6 回查其确定位置。C 对 Q₀ 保留旧预测造成的漏报，对 Q* 核对修订预测及独立裁决，两版各自合格后冻结。若所揭示证据支持原条款，keep 决定直接交 C，无需构造空修订。

## 故障与回退走查

| 注入位置／事件 | 恢复应读取什么 | 正确的账本与动作 |
| --- | --- | --- |
| 选择写入前或事务中断 | Command 和已提交事务 | 无完整记录则重新提交；无孤立扣费或派发 |
| 选择已提交、派发前崩溃 | 已登记 queued 请求 | 重用 request_id 派发；余额不变 |
| 已派发，当前租约有效、无完成回执 | 当前 attempt/token、心跳／启动身份 | 等待或重新监听；不新建尝试 |
| 进程已结束，有完整回执，未提交发布 | 当前尝试的完成回执及全部摘要 | 取回，条件提交 T1；不必再次编译或执行 |
| 无回执且当前尝试已死／超时 | 逻辑请求、当前围栏、重试上限 | 事务废止尝试 1 并创建尝试 2，不再扣费；尝试 1 迟到归档 |
| 刚完成时遇到并发回收 | 两事务共同检查 request.active_attempt 和状态 | T1 先提交则只恢复发布；回收先提交则旧回执失去资格 |
| 仅有半写文件、回执摘要不符 | 回执及其绑定的私有输出 | 隔离、记录协议错误；按基础设施策略恢复，不生成标签 |
| T1 已提交但正式对象尚不存在／对象已提升但 T2 尚未提交 | 发布意图、暂存／正式对象摘要 | 补发布或补 T2。ready 之前角色清单不能引用 |
| 已 ready 但未揭示／已揭示但角色未收到 | 组内首次 Reveal 和授权清单 | 前者提交交付；后者复用同一 Reveal，重发清单，旧水位不变 |
| 重复结果／同一有效尝试不同结果 | 原接纳的回执摘要与尝试身份 | 相同则幂等；不同则 conflict。保留历史，停止自动消费并复查依赖 |
| B4 发现容量来自错误对象 | 绑定和契约的直接依赖 | 回 A2，重验相关证据；原小域反例不得用于新对象 |
| B4 的全部解释被反驳，但骨架与契约仍可信 | 同组已揭示证据及其版本 | 回 A5，保留有效观测、余额与可见快照；新解释标 post_remodel |
| C5 发现实现偏差，Q₀、Q* 各余 1 | 该版本的父查询、诊断及修复意图 | Q₀ 的修复请求使余额变为 0／1；物理重试仍是 0／1；再需修复则 Q₀ 回归失败。Q* 的余额独立 |
| C5 发现 Q* 忠实但规约偏差 | 对齐表和规约预测 | 返回 B4；登记决定而非消耗一次新的 C 修复意图 |

## 复核结论与验证边界

设计复核确定了两处容易产生相反恢复动作的边界。第一，已登记发布意图必须先恢复发布；否则租约到期可能让同一请求既重跑又接纳结果。第二，按本组首次可见历史判定事后预测；用另一组的 seq 或勘误的新 seq 都会误判。

另在临时 SQLite 3.53.1 数据库上完成七项最小事务核对：未提交事务关闭重连后的整体回滚、重复命令只扣一次、额度不足整笔回滚、围栏条件更新拒绝旧尝试且只接纳当前尝试一次、跨组独立扣费与首次揭示查询、后续勘误保留原暴露时间、Q₀／Q* 预算独立且重试幂等。该核对使用简化表和串行事件，验证的是上述数据库约束的可表达性。

完整协调器编码后仍须验收真实进程强杀、并发事务与监听竞态、租约跨重启、Windows／WSL 目标文件系统的发布耐久性，以及受限工作进程能否越过 manifest 读取文件。设计阶段通过正向和故障走查；上述运行时行为尚待实现验证。
