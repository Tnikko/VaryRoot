# VaryRoot 框架设计

**状态：设计稿。** 当前交付物是方法定义和实现契约。实现边界为本地给定的 C/C++ 补丁、源码快照与开发材料；首版语言前端支持空指针解引用和连续缓冲区越界访问。独立评测在框架落地后接入。

## 1. 研究问题与系统接口

一个补丁常常同时改变多个程序事实。不同规约可以解释同一修复，却对另一个访问作出相反判断。VaryRoot 研究如何显式表示这些解释，主动构造能区分它们的对照，并将证据支持的条款变化落实到静态查询。预期方法贡献集中在两个接口：从竞争解释得到可裁决的案例，从条款修订得到可追溯的查询差异。

输入包括前后版本、补丁、访问位置、可引用的接口契约与分析范围。输出包括初始规约 S0、定稿规约 S*、各自的查询 Q0 与 Q*、决策记录和构建清单。证据足够时可以修订或保留，证据不足、条款无法表示或后端无法实现时，返回带原因的部分结果。调用者可以判断流程止于哪一步。

## 2. 模块、读写权限与职责

| 模块 | 接收 | 交付与边界 |
| --- | --- | --- |
| 源码前端与 A | 版本化源码、补丁和契约 | 建立访问位置、对象关系、控制与数据依赖的来源索引。A 提议精简骨架和候选解释，每项桩函数假设引用来源或标为待核准 |
| 规约解释器 | 类型正确的条款、目标位置的程序事实 | 输出三值预测、适用域和推导依据。同一解释器服务 A 的候选检查、B 的分歧选择及 C 的回归 |
| B 与案例选择器 | 候选解释、受控变化、此前已揭示的本组证据 | B 提议对照，选择器接受登记预测并作确定性选择。候选保留共同前提、允许变化的因素及对应位置 |
| 独立验证器 | 被选案例、目标操作契约、观察域 | 输出违规见证、带覆盖依据的保护结论或待定。标签计算与候选解释及查询输出隔离 |
| 决策与版本管理 | 已登记预测、独立证据和原始条款 | 归因于案例、解读或条款，交付带父版本的决定及依据；勘误以追加记录保留原决策上下文 |
| C 与 CodeQL 后端 | 规约、谓词库、源码数据库和位置映射 | 输出查询、条款到谓词的映射及逐位置回归结果。无法翻译的条款显式返回后端缺口 |
| 本地协调器 | 各阶段工件及运行配置 | 独占状态提交权，落实输入白名单、阶段转换、恢复和冻结。模型输出先作为提案保存，经校验才能成为下一阶段输入 |

## 3. 规约 IR 的语义

规约以一次访问为中心。对象身份、指针值、事件、字节数、元素数和位置是不同类型。四字段 Source、Propagation、Guard、Sink 各自引用类型化变量；每条规则声明适用域、前提、结论、逻辑方向和来源。首版支持对象相同、状态判定、路径是否阻断、同一对象上的区间包含，以及显式单位转换。缺少元素大小或对象绑定时，解释器保留未知。前端事实均附源码跨度或契约依据。

对每个位置，先判断适用前提，再独立尝试推导“应报”与“不应报”。只能推出一方时给出相应预测；两方均无依据时记录未覆盖及原因；两方同时成立时退回冲突条款。保护的充分条件只支持正向推导，未匹配该条件不能自动导出应报。实现默认无告警发生在查询输出层，规约层仍保留未覆盖。

例如，规约“单字节访问且偏移落在目标容量内，则保护”同时约束宽度、对象身份和单位。宽度未知时，解释器列出缺失事实。另一条规约“任意正宽度访问只要起点合法就受保护”对相同位置可作明确预测。两者在适用域上的差异会进入选择器，模型无需在看过标签后重新解释原句。

## 4. 证据驱动的状态转换

正常路径依次为种子登记、候选规约接受、预测登记、选择提交、证据揭示、归因与决定、双版本编译、逐位置回归和冻结。允许从决定回到候选规约阶段开启下一轮。每次转换记录种子、组、轮次、输入摘要和产生的工件。显示给模型的上下文由当前状态构造；摘要用于校验一致性，标签的可见性由运行权限控制。

1. **候选接受。** 每个解释须在声明域内对种子前后给出有依据且与已核实证据一致的判断。解释无法形成、修复后仍存在相关违规或骨架契约未经核准时分别记录。修复后的正常路径既可能绕过原操作，也可能在状态已合法时继续使用对象。
2. **对照生成与选择。** B 先指出争议条款，再提出单因素变化。对照清单同时记录保持条件及其验证依据。选择器在预算内优先覆盖尚未区分的硬分歧解释对，其次覆盖明确预测与未覆盖之间的差异。并列裁决及验证单位由策略版本规定。只有证据反驳某个明确预测才能据此排除该解释。
3. **证据与归因。** 正例需追溯到指定对象及位置；反例需正常功能可达，且有声明域内的完备性依据。待定、超时及运行失败分别记录。若所有竞争解释都被反驳，回到候选构造并保存已失败假设；若仍有多个解释与证据相容，输出剩余分歧。预算耗尽不能充当保留或修订的证据。
4. **保持可重放。** 同一阶段重试复用已提交的选择及工件。模型调用的输入、输出和版本单独保存；重放使用已保存提案，重新调用模型产生新分支。只有完整写入并验证的工件才能提交状态转换。

## 5. 规约到查询的编译边界

解释器在受控开发案例上给出规约预测，后端则面向源码数据库中可提取的事实。两者共享原子条款的定义和类型签名，并分别记录事实来源。C 为每条受支持的操作选择已版本化的谓词实现。提议新增谓词时单独审查其语义和适用域，避免在查询内隐式扩大或收紧规约。增量编译按条款依赖确定受影响谓词，同时回归全部确定开发位置。

回归按源码版本、目标表达式及预登记的源码跨度匹配。Q0 的实现验收依据是 S0 的明确预测及默认；其中与证据的偏差保留为基线。Q* 还需满足确定开发案例的证据要求。无法提取事实、规约冲突、后端缺口、位置映射歧义与实际误报漏报分列。通过门禁后，冻结规约、查询、谓词库、工件清单、位置映射及数据库和工具版本。

## 6. 实现顺序与框架交付边界

| 实现阶段 | 可独立验收的交付物 |
| --- | --- |
| I · 类型与工件 | IR 文法、类型检查器、三值解释器、位置标识和版本化文件格式；给定规约与事实即可重放完整推导 |
| II · 协调与提取 | 状态转换器、按角色构造的输入、断点恢复、源码前端及 A 的来源索引；任一条款可回溯到源码或显式假设 |
| III · 校准内环 | 候选构造、变化描述、选例接口、证据适配器和决策记录；支持修订、保留、未决及重新建模 |
| IV · 查询外环 | 条款到谓词的映射、双版本编译、位置回归和冻结；支持从冻结包重建并解释每一处查询差异 |

四阶段组成首版框架的实现范围。验收关注接口语义、错误处理和可重放性。研究效果、跨项目迁移和复核成本在框架落地后按[独立评测与试验协议](workflow.md)评价。
