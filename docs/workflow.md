# VaryRoot 首轮实验工作流

本文记录后续实验协议和已有 pilot 的历史口径。当前建设主线及模块接口见[框架总体设计](architecture.md)。

本轮检验同一预算下，按解释分歧选例能否比随机选例更有效地校准规约。实验单位为一个种子上的一轮校准；历史检出的计数单位为经人工核准的独立修复簇。第一批数据位于 [pilot-v1](../data/pilot-v1/README.md)。工作流由本地文件驱动，A、B、C 是职责边界，可由脚本或人履行。

## 从种子到冻结包

| 顺序与执行者 | 可以读取 | 写入本轮目录的交付物 | 验收或失败处理 |
| --- | --- | --- | --- |
| 1 · 种子整理与 A | 开发种子的公告、修复前后源码、接口契约 | seed.json 记录修复簇、两个版本、函数及目标位置。spec-initial.json 记录 Source、Propagation、Guard、Sink、条款适用域和原文依据 | 抽取后对照原代码核实对象、单位和控制流。无法独立支持的契约逐项标记，抽取失败仍计入种子总数 |
| 2 · B 登记预测 | 初始规约、种子前后标签、公共候选池 | predictions.jsonl 逐条记录种子、轮次、解释、案例、位置、三值预测和依据。selection.json 记录池的摘要、算法、随机种子、预算和选中 ID | 预测与选择先落盘并计算摘要，然后才向验证器请求观测 |
| 3 · 独立证据验证 | 被选中的案例、契约、有限输入域 | evidence.jsonl 记录版本、位置、输入、路径结果、正常见证、违规见证或完备性依据；证据缺口标记待定 | 验证器只用目标对象契约定标签。编译失败和超时单列并消耗尝试预算 |
| 4 · B 校准 | 本组已揭示证据及原预测 | decision.json 记录证据修正、预测勘误、修订或保留；spec-final.json 保留依据和适用范围 | 回查本组所有确定开发位置并记录旧预测。两组之间禁止交换选择结果、证据和修订 |
| 5 · C 回归与冻结 | 每组的两版规约、本组开发位置、预登记默认 | regression.jsonl 按版本、文件、函数、目标位置连接证据标签、规约预测与实际告警。freeze.json 记录输入、规约、查询、数据库、依赖和工具版本的摘要 | 未覆盖默认无告警，证据正例仍计漏报。实现缺口单列。确定开发位置未通过的最终版本保留失败记录 |
| 6 · 评测者 | 冻结包、独立历史修复簇及预选仓库 | 配对命中表、并集复核记录、耗时与失败分母 | 每簇预选一个修复前版本和目标；多文件问题预先确定允许匹配的位置。反馈转入下一版本 |

同一运行以种子 ID、策略、重复号唯一标识。重试复用已登记的选择和证据，变更规约、案例池或输入域时另开版本。各组独立修订，C 在两组间共享相同条款的查询实现和修复预算。种子前后构成基线，不占选例预算。

## 首轮对照

试运行先固定候选池和解释，一次选取一批，再揭示证据。每个合成类别含一对种子与十个候选位置。以单个位置为一个验证单位，建议预算 K=4；两组均从十个候选中无放回选择四个。随机组用预登记整数种子 11、23、47，分歧组按相反明确预测的解释对数降序，同分按案例 ID。预测未覆盖不算相反；若分歧不足，依次从剩余池按 ID 补足并标记。两种方法共用同一池、解释、验证器、目标位置和预算。三次随机抽样属于同一种子的重复测量。

端到端直接生成查询与未校准 Q0 是两条参照线。前者仅获种子材料、共同的时间与查询修复预算；固定模型、提示版本和可重试次数。后者忠实实现初始规约。记录每组尝试数、可定标签数、排除解释数、筛选与验证耗时。报告逐种子的新增及丢失命中，并列出抽取失败、保留原规约、待定和实现失败的数量。

首轮可执行对象是 NPD、OOB 两个合成种子对。每对只绑定同类的十个候选位置。真实开发种子单独立项，先核准根因、位置与适用契约，再按该种子建立各组共用的候选池和适用历史簇清单。合成种子的回放结果单独报告。

两组开始选择前锁定 Q0 和共享条款实现，各组后续变更留在各自运行目录。可以运行且通过全部确定位置回归的最终版本才获得冻结编号。无法运行和回归失败分别计入种子流程结果。只有两组都有合格冻结版本时，才在共同预选簇上直接比较命中；已冻结组的单组结果另列。每个种子展示三个随机重复的原始结果及成功冻结次数。主要配对比较使用三次均冻结且分歧组冻结的种子，计算分歧组的命中簇数减去该种子三个随机组命中簇数的均值，同时报告共同入组数和排除原因。已运行后的零命中照实计入。

## 数据隔离与适用边界

开发执行者只接收开发目录及本组本轮的选择。评测保管者负责 reserve 清单、近重复归组和冻结后分发；目录隔离须由运行时采用输入白名单落实。开发过的仓库不能计入整仓未见评测。本批跨项目预留同时改变了语言和项目，结果仅用于迁移观察，无法单独归因于语言。历史同根因判断按具体对象、状态、保护和操作复核，CWE 只作初筛。同一 PR、回移或共用修复要联审。

合成夹具使用标记调用记录访问意图，支持有限域验证、规约预测与位置连接。正式历史评测需另行确认实际内存访问位置。两类结果分别报告。整仓复核需在冻结前另行预登记项目、固定版本和审阅抽样方案；开发过的案例不能转为独立评测样本。

整仓复核取参加该轮的全部冻结查询（含两条可运行的参照）之并集。先按仓库版本、操作位置和根因归并，同一问题只审一次，然后按各查询的命中成员组合分层抽样。保留各层规模、抽样概率、待定数和复核时长，按抽样概率倒数加权回算各查询的确认数与复核成本。

## 下一版工作流设计决策（待实现）

**条款与预测。** A 交付四字段规约，每条记录条款 ID、版本、对象与单位绑定、适用前提、逻辑方向和源码依据。以 G 表示匹配到保护形式，以 P 表示本次使用受到保护。「G 足以保护」记为 G ⇒ P，「只有 G 才能保护」记为 P ⇒ G。后者允许由非 G 推出非 P，但单凭 G 无法推出 P。只有两个方向均有依据时才登记为充要条件。三值预测先检查 Source、Propagation、Sink 和适用前提，再合并条款结论；缺少依据留为未覆盖，相互矛盾则退回修订。匹配不到一种保护写法本身不能充当证据标签。

**提取与校准。** 依赖切片可为 A 提供候选上下文。桩函数的每项保证仍需回指原接口，抽取失败与证据不足分别记录。种子门禁核对修复前的违规见证、修复后的安全行为及正常功能；修复也可能通过调整容量或宽度，使目标仍可安全到达。B 为每对案例声明允许改变的语义因素及应保持的契约。AST 差分可发现额外改动，单因素是否成立仍需核对对象、单位与路径。预测勘误追加记录，原预测保留用于还原当时的选择。

**选择器作为独立实验组。** 在新的预登记批次中，保持候选池、解释集和预算一致，比较随机、pilot-v1 的逐例硬分歧计数、贪心新增覆盖。贪心组按每次新增的硬分歧解释对数优先选例，同分参考新增的「明确预测／未覆盖」解释对数，再按案例 ID 裁决；两类集合分别更新。两类增益均为零时按预登记回退策略补足并标记。覆盖域差异用来定位规约空白，排除解释仍需与其明确预测相反的确定证据。pilot-v1 每类只有两个解释，第一个硬分歧就覆盖唯一解释对。检验贪心机制应另选具有多个真实竞争解释、候选能区分不同解释对的种子，并单列为此增加的构造成本。

**实现与冻结。** C 对已有后端支持的条款复用版本化谓词，复用键包含条款语义、绑定和适用域。回归先按固定源码版本、文件和目标表达式标识定位，再按预登记的源码跨度映射告警；同一行内有多个访问时必须区分，映射歧义单列。冻结摘要供复核文件一致性。正式盲评另由独立评测者在揭示标签前保管登记摘要，并限制各组进程的可读输入。OOB 边界代表点用于找分歧，确定反例仍需声明域内的穷尽或覆盖证明。

## 实验记录的本机副本

每个实验或工程检查点生成报告后，在本机 `F:\RootVary\server-reports\` 下建立独立目录，复制报告、可复核的原始记录或证据归档、测试日志及摘要清单。核对本地文件 SHA-256 与服务器记录一致，并在该目录的 `manifest.json` 登记服务器原路径、文件摘要和同步时间。最终交付时同时给出本地副本路径；同步或校验失败则明确记录为未交付，不把仅在服务器上的报告视为完成。服务器上的原始记录保持原位。
