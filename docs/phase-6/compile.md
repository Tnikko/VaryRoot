# C1–C2 · 输入与条款编译契约

每个组、重复号和运行分支独立编译一对查询。C1 由协调器锁定输入，C2 可由模型提出局部谓词实现。两版的可比性取决于同一事实如何解释，以及同一个未改条款最终用了哪一份代码。

## 输入清单

| 输入 | 核验与失败去向 |
| --- | --- |
| 本组 spec_ready、Decision、证据水位、基线与定稿引用 | keep 核对 S* 与首次 S₀ 同义且无修订；revise 核对从首次基线经重新建模、修订至定稿的完整版本链。待定停止包留在 B。输入过期时按依赖重验 |
| 案例与位置 | 从 B6 接收本组全部确定位置 M、父子目标映射、契约、域、裁决版本；另收待定与失败索引。两版均在同一 M 上重放对应规约，包括较晚产生的开发位置。分别标记初次预登记及事后回放 |
| 编译输入 | 登记共享谓词库、IR 解释器、条款规范化器、默认策略、匹配器、能力表、源码及数据库快照的内容摘要，锁定 QL 包、提取器、工具链与构建配置。两版等额修复预算分账。只向 C2 提供实现所需的条款、绑定、能力与诊断；证据标签由 C5 对照 |
| 原始基线 | 继承选例前登记的共同基线引用与已有代码摘要。若实施比较协议已锁定 Q₀ 可执行版本，后续修正形成带父引用的新构建；保留原始实测，不能以修正后版本追认此前的基线。跨组比较要求基线构建摘要一致 |

## 条款到谓词的绑定

每条映射登记 clause_ref、Source／Propagation／Guard／Sink 角色、规范化条件、逻辑方向、变量类型及身份、适用域、所依赖的事实关系和语义版本。由上述语义键查到唯一的模块、导出谓词、参数顺序、实现摘要及传递依赖摘要。语义键不能只取条款编号或自然语言相似度。版本别名须有同义依据；无法核准等价时停在 C1。组成规则的量词、否定、合取与路径绑定也是编译依赖，禁止拼接不同路径的事实。

对于共同语义键，两版以同一锁文件解析至同一实现。C1 生成基线到定稿的条款与依赖差异清单；每个专属谓词或组合逻辑变化均须追到经核准的条款变更。重建解释时须包含 remodel 决定，最近一次 Revision 只描述其父版本到子版本的变化。源代码哈希只能证明实现相同，不能单独证明模型正确或差异都由修订造成。C5 另做位置级核对。

C2 先复用已锁定实现，再为缺少实现但有后端事实支持的条款提交提案，附所需输入、定义域、未知值处理及可复核的绑定。禁止引入目标 ID、文件名、裁决或案例特判。被拒提案留存。共同依赖有缺陷时，须成对升版库并使两侧受影响构建失效；同一修复涉及两版时，先在一个事务内检查并分别登记两侧修复意图，各扣一次，各自后续重跑幂等。若某侧无余额或研究批次已锁死公共库，本批交部分结果，另立构建版本；不能只改一侧的公共逻辑。

## C/C++ OOB 能力表

以下是首版后端**拟支持并须逐环境核准**的范围。C1 在读取本轮结果前，按提取器、库、数据库和事实绑定版本登记每项为 supported、unsupported 或 unverified，附能力夹具或核查记录。后两类均不能充当实现完备的依据。

| 访问形式或保护 | 可声明支持的前提 | 缺项记录 |
| --- | --- | --- |
| 已知对象的单次、正宽度定长访问 | 能唯一绑定对象代次、有效容量、目标偏移、访问宽度，且可核实各自单位与原程序转换语义 | 按位置登记具体缺失事实，如对象可绑定而宽度不可提取 |
| 元素索引换算或跨多个字节的访问 | 元素大小和 ABI 已知，转换与运算语义可表达，能判断完整区间；偏移和宽度位于同一路径条件下 | 仅支持起点检查不足以声明完整区间条款可实现 |
| 通过条件分支保护 | 同一对象、定义及目标上下文中，能够证明该条件覆盖的故障路径确实绕过访问或到达时区间已合法 | 只有文本相似的比较不能声明为已核准保护 |
| 动态宽度、复杂对象绑定、模型未核准的整数转换或零宽度接口 | 每种形式单独登记能力与适用契约，未核准前保留缺口 | 输出 capability_ref、受影响条款／目标、诊断、可运行部分和复核条件 |

如果 1B 由于规约域外而输出 uncovered，走预登记默认。如果 1B 的事实快照足够、预测明确，但后端取不到事实或无法表达条款，保留原预测并登记 backend_gap。数据库选错构建配置先归为输入错误，可纠正后重判能力。[解释器语义](../phase-1/inference.md) · [B6 交接](../phase-5/decision.md)
