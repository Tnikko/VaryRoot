# C2–C4 · 构建、告警与目标表达式对齐

C2 的产物是带条款映射的实现提案。C3 由程序检查依赖并分别编译 Q₀、Q*，在同一只读数据库上执行。每次构建记录 lane、父构建、输入摘要、命令及配置、退出状态、原始输出摘要和完整性标记。编译失败、提取失败、超时、结果截断与成功的空结果分别登记。失败仍可保留原始诊断；只有完成且可解释的结果进入位置计分。

## C4 匹配顺序

1. 在读告警前建立目标索引。按源码版本、构建配置、规范文件身份和文件摘要锁定目标；用同一份源码字节把后端行列转换为半开字节区间。坐标配置须声明行列起点、端点是否包含、字符编码及列单位。未知坐标约定须先校准。记录拼写跨度、展开来源、目标访问角色、作用域、AST 节点与所需调用上下文。
2. 为每个目标预登记可接受的**主告警表达式**，包括经批准的父子节点映射。把后端节点或表达式身份连接到这些目标。路径中的相关位置、同一行、最近跨度、包含该访问的整条语句，均不能自行证明主位置命中。版本或数据库不符退 C1/C3。
3. 先检查目标的后端表示是否可唯一识别，再处理告警。一个后端身份碰撞到多个 TargetRef，只有经核实的访问角色、语法节点或上下文映射能消歧；后端没有输出该信息时标 ambiguous。前端拥有两个不同的 AST 序号本身无法为后端选择其中一个。映射无依据记 unmappable，两者都阻断受影响位置及整组冻结。保留未受影响位置的可计分结果。
4. 完整运行、目标可唯一观测，且有一条或多条主告警唯一指向它，记 hit；保存所有原始告警引用，位置只计一次。以上前提满足且没有这样的告警，记 no_alert。其他位置的告警单列。任何可能属于该目标的未决告警都先阻断该目标的结论，即使列表中还有同一行其他告警。
5. 只修正坐标换算或映射时，升版匹配器／映射，复用原始完整输出，对两版重做受影响匹配和回归。若须改变查询输出才能识别表达式，转 C2 按查询修复计费。经核查仍无法对齐则部分交付，不能用移出 M 的方式通过。

| 走查输入 | C4 结果 |
| --- | --- |
| 同行左、右两次访问，只有右侧一条精确告警 | 左侧 no_alert，右侧 hit。若目标只有左侧，右侧告警记为目标外 |
| 单个目标收到两条同主位置的告警 | 一次 hit、两条原始引用 |
| 阶段 3 的两个宏访问，拼写区间同为 [179,185)，展开起点均为 174 | 只返回这些坐标则两处 ambiguous；若经核准的后端节点映射可分别解析这两处，再按各自原始输出计分 |
| 同一内联函数体，两次调用对应两个预登记目标 | 没有可验证的调用身份时不能把一条告警分给任一调用 |
| 条款明确，后端缺宽度事实，目标节点仍唯一且查询成功返回 | C4 照实登记 hit 或 no_alert，携带 backend_gap 进入 C5。若整个查询无法运行，实际输出记 unavailable |
