## 7server 命名空间协调器增量执行记录

本次在 `/dev_sdb/tq/VaryRoot` 内导入并锁定原 VM 的 Agent A、验证器、
选择器与步骤 03 通用角色四份根文件系统。生产协调器以
`VARYROOT_ROLE_BACKEND=namespace` 和项目内 `image-lock.json` 显式选后端；
锁缺失、镜像 ID 未登记或解包摘要变化直接拒绝，没有 Docker／宿主回退。
根文件系统与输入只读，输出按尝试独占，网络命名空间仅见 `lo`，
非 root 且 `CapEff=0`、`NoNewPrivs=1`，无 Docker socket。
角色执行审计在 SQLite 中按请求与尝试绑定后端、镜像 ID、根文件系统摘要和退出状态。
七个角色／阶段白名单视图、随机选择器的四文件视图、延迟子进程超时回收、
四条文件事件链、真实 Agent A `draft→seed_pending` 与验证器 A4/A6 主链均有实测。
Clang 18.1.3 锁定文件及验证器 registry 中的原生二进制摘要逐项核验。
[检查点复核](../runs/7server-namespace-v1/review.md) ·
[机器摘要](../runs/7server-namespace-v1/summary.json) ·
[镜像锁](../toolchains/namespace-v1/image-lock.json)。

该增量不改变 R04：真实存储断电耐久仍待验。命名空间后端没有 Docker
`--memory` 与 `--pids-limit` 的同等 cgroup 限额；本轮实测的是文件、
网络、权限和超时围栏隔离。7server 宿主缺少 `/usr/bin/clang-18`，直接在
宿主运行旧前端／原生编译单测会报 `parse_context_missing`；生产角色在
锁定的私有根文件系统内运行，单独按本次定向回归记录验收。
