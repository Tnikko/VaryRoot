# B1–B2 · 对照案例提案与准入契约

输入为已接受种子、当前工作规约、竞争解释及本轮授权材料。B1 的模型职责是提出一对能检验具体条款的受控变化。B2 的程序职责是核对提案并决定是否准入。一个案例是否值得验证，与它是否满足受控对照条件分别登记。

## 提案记录

| 字段 | 内容与验收依据 |
| --- | --- |
| proposal_id、parent_refs | 版本、组／公共池归属、父种子或父案例、产生提案时的上下文快照 |
| disputed_clause、factor | 争议条款、选择的变化因素、为何它可能改变预测。标记预期保持或翻转；该标记属于提案作者的假设 |
| left_target、right_target | 各自的 TargetRef、变体版本、父子映射、访问角色。一个比较连接两个位置，每个需新揭示的位置分别计验证单位 |
| allowed_delta | 明确允许改动的语义因素、受影响节点及必要的派生改动。例如改变宽度会改变常量、类型化 AST 节点及请求区间，仍可属于同一受控因素 |
| structural_invariants | 可机检的父版本、作用域、目标身份与操作角色、契约及域引用、未改区域的归一化 AST／控制流签名、相关定义与使用位置 |
| semantic_invariants | 保证等价的条件、适用域、来源和核准者，如包装接口的失败模式、对象与容量的对应、清理出口可达性。签名相同不能代替契约依据 |
| coverage_dependencies | 可用验证器、独立访问契约、观察域及正常功能要求。当前阶段只核对能否取证，不要求预知裁决 |

七类变化因素沿用项目定义。各提案逐项声明应保持的内容。例如“改检查对象”允许受检对象变化，但实际使用的对象须保持；“替换目标操作”允许读写角色变化，但要求核准二者共享待检前提。机械要求所有因素都保持相同会拒绝这两类有效对照。

## 准入优先级

| B2 发现 | 结果 | 账本与去向 |
| --- | --- | --- |
| 引用、快照、作用位置或类型失效 | invalid | 记录诊断，退 B1 或位置前端 |
| 改动超出 allowed_delta，或结构不变量被打破 | confounded | 记录具体多出的变化，退 B1 分成独立案例 |
| 必需的语义保证、对象映射或契约缺少依据 | needs_support | 暂缓入池，补核准依据；若父骨架失真退 A2 |
| 结构核对通过，必要语义依据可追溯且获核准 | admitted | 发布候选位置、配对关系、共同条件及变更记录 |

前三种结果均不进入可选清单，不提交 selection、不创建验证请求、不扣 B.verify 预算。生成、筛选及人工核准时间照实记录。入池后不以标签好坏删例。验证结果 pending 与入池前 needs_support 分开计数。

**判例。** 在容量 8 字节、偏移 6、同一目标对象下，将访问宽度从 2 改为 3，独立容量依据与域约束不变，两例分别固定宽度这一受控参数，可准入。若同时改为另一缓冲区且改用元素计数，则位置身份和单位也变了，退回拆分。候选案例对并不自动获得两个已知标签；若只选择其中一端，只揭示该端，另一端的证据须有既有合法来源或另行付费。
