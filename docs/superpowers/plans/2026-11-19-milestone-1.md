# 里程碑 I 编码实施计划（待审）

**交付目标**　在本地用版本化的 JSON 文件重放一个规约对指定位置的判断，返回可核对的事实、条款、路径、缺项或诊断。01 与 02 合并提交审批，分别设验收点。通过 01 才执行 02；完成后提交代码、测试与复核记录，由项目负责人审核后再进入 03。

**实现选择**　拟用 CPython 3.13、标准库 unittest 与 UTF-8 JSON，包目录拟设为项目根的 varyroot/，可直接从根目录运行模块。本批先实现受控 IR 的读取、校验和推导；无需访问在线模型、数据库或历史缺陷数据。现有 pilot 是有独立格式的研究材料，开发测试使用新建合成工件；若引入旧材料，需显式适配版本。[工件表](../../phase-1/artifacts.md) · [解释器推导表](../../phase-1/inference.md)

## 从详细设计到建设顺序

| I · 01 共用工件与规约 IR | 落实 1A，交付版本引用、位置、事实、契约、域、条款、判断与交接格式 | 文件往返、跨工件校验；keep、revise、unresolved 可区分 |
| I · 02 规约解释器 | 读取 01 快照，提供 A6、B2、B6 和 C5 共用的纯推导接口 | 给定同一输入可重放预测、缺项和冲突见证 |
| II · 03 本地协调器 | 使用 01 工件、02 推导接口，实现状态、SQLite 账本、围栏、manifest 和发布恢复 | 接入上下游契约桩，四路径经过真实文件边界；并发恢复与角色隔离另取运行证据 |

## 01 验收点 · 文件能独立解释

- [ ] **01a 工件读取与版本边界。** 拟建 varyroot/artifacts.py、tests/test_artifacts.py。接口 load_bundle(path) 读取清单及明确列出的文件，validate_bundle(bundle) 返回带错误位置的诊断。逐项落实通用字段、版本绑定、引用存在性、唯一身份及无环依赖。区分显式 null、字段缺失、数值零、布尔假和未知事实。无法识别的 schema_version 显式报错；固定片段上的 UTF-8 半开字节跨度、快照摘要与变体身份可核对。先构造合法最小包，再依次破坏版本引用、文件跨度、身份和依赖，验证诊断能定位到字段。
- [ ] **01b IR 与事实。** 拟建 varyroot/ir.py、tests/test_ir.py。对四类条款、逻辑方向、作用域、元变量类型和五类关系签名进行静态校验。未声明的符号或不合法的类型组合是 invalid_ir；合法声明但本次无值是缺失事实。分开表示源码事实、接口保证与骨架假设及其核准状态。测试错误对象、单位未知、元素数直接与字节数比较、未核准假设和同一目标的不同域版本。
- [ ] **01c 决定与交接。** 拟建 varyroot/handoff.py、tests/test_handoff.py。工件覆盖 TargetRef、Fact、Clause、Prediction、Observation、Verdict、Decision、Revision 及引用的 Contract、Domain、规约版本与快照。交接记录要求字段 revision_ref 存在，允许值为 null。keep 必须绑定原规约与 Decision 并核对零语义差异；revise 必须有可解析且指向触发决定及相应父子版本的 Revision；unresolved 可无 Revision，终态不可送 C。交接记录引用 Decision 与 Revision，避免在不可变工件间制造双向依赖环。核对修订四元组改变／保持分类及唯一引用；B6 的真实分母由 06 的组内台账重建。验收覆盖合法三路径、缺字段、错误父版本、冒充 keep 和过期引用。此处只定交接契约；C1、C6 在 07 消费同一契约。
- [ ] **01 独立复核。** 从项目根运行 python -m unittest discover -s tests -p "test_*.py" -v，留存命令、版本与成功／拒收样本。至少一份合法文件由另一进程重新读取。先对失败样本确认预期诊断，再验合规包；结构不通过不得进入解释器。

## 02 验收点 · 推导能独立重放

- [ ] **02a 三值关系。** 拟建 varyroot/inference.py、tests/test_inference.py。公共入口 evaluate(spec, target, contract, domain, facts) 返回带推导的结果或诊断。逐项测试 T/F/U 的合取、析取、否定，以及对象身份、空状态、路径阻断、单位转换、区间包含五类关系。逻辑失败和事实未知分别溯源；未绑定值不得按 false 求值。
- [ ] **02b 位置级闭合。** 分别计算 report 与 quiet 的证明，再合并为 report、quiet、uncovered 或 spec_conflict；无效输入走 invalid_ir。report 要在同一可行、到达的路径和同一对象上闭合全部前提。quiet 要有完整覆盖与充分保护；空路径表本身不能证明安全。冲突保留两棵证明树；未覆盖列出缺失事实或域外原因。测试跨分支拼接、空完备集合、双向可推导、必要条件为假但缺 Reaches，以及已退出和状态已恢复的两种证明。
- [ ] **02c 文件入口与回放。** 拟建 varyroot/__main__.py、tests/test_replay.py、tests/fixtures/m1/。拟提供 python -m varyroot validate <manifest> 和 python -m varyroot explain <manifest> <target-id>。每份解释请求清单绑定具体规约、契约、域及事实版本。标准输出为机器可读 JSON，合法三值预测正常返回，冲突／无效输入返回不同诊断及非零退出码。解释结果为尚待登记的内容；登记类别、commit_seq 与证据可见水位由 03 在提交时赋予。两个独立进程重放同一快照，对照预先写定的期望结果与关键证明引用。改变无语义顺序应保持结论；对比同一位置的两个规约快照可解释判断变化。
- [ ] **02 复核包。** 同一测试入口重跑 01 和 02，附逐向量结果、实际命令、未通过项及台账更新。NPD 以记日志继续、提前退出、等价绕行、修正后继续分别验收。OOB 使用独立容量 8 字节、偏移 6、宽度 2／3，旧起点规约应为 quiet／quiet，完整区间规约应为 quiet／report；单字节域为 uncovered／uncovered。容量单位缺失时返回 uncovered 和缺项；错误类型声明拒收。分别核对预测值与依据。[NPD 期望](../../phase-1/npd.md) · [OOB 期望](../../phase-1/oob.md)

## 后续接线和证据归属

03 的契约桩从一个公共输入清单开始，经单独进程生成 A 包、验证回执、B 交接和 C 结果。每段从磁盘重新反序列化，对照预登记期望清单核对字段、版本、状态与允许的读集。修订与保留走到测试用成对发布，未决在 B 停止且无 C 请求，后端缺口在 C 部分交付且无冻结编号。四条路径在 04–07 逐步替换真实组件，测试发布物与研究运行分开。独立的[运行时验收台账](../../runtime-acceptance.md)记录每项的责任步骤、证据及状态；断电耐久只在对应存储环境取得直接证据后销项。

**审批范围**　本次只申请执行 01 + 02，合并审批、分步复核。03 的契约桩、后续真实工具链及项目效果实验均有独立验收时点。
